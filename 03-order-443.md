# Order 443: Defensive Hardening (WAF & IDS)

**Type:** Blue Team · Detection & mitigation engineering\
**Stack:** ModSecurity (WAF) on Apache2 · Snort (IDS)\
**Result:** 3 WAF rules + 4 Snort rules deployed and validated in real time

## Objective

Starting from the attack vectors exploited in the offensive phase, design, deploy and document specific defensive controls to detect and block them. The goal was not exploitation but the correct implementation of security controls.

## Attack vectors defended

|   | Vector | WAF rule |
|---|--------|----------|
| 1 | Path Traversal / LFI (`?lang=../../../../etc/passwd`) | 1000001 |
| 2 | PHP webshell upload disguised as `.jpg` | 1000003 |
| 3 | Command injection / RCE via parameters | 1000004 |

## WAF rules (ModSecurity, `SecRuleEngine On`)

| ID | Purpose | Variable | Operator | Action |
|----|---------|----------|----------|--------|
| 1000001 | Block Path Traversal / LFI | `REQUEST_URI\|ARGS` | `@rx \.\.\.` | `deny 403` |
| 1000003 | Block `.php` file uploads | `FILES` (inspects content, not just name) | `@rx .php` | `deny 403` |
| 1000004 | Block RCE command keywords | `ARGS` | `@pm whoami id uname ifconfig cat nano` | `deny 403` |

**Design note:** the Path Traversal pattern uses the generic `\.\.\.` rather than `\.\./` because the specific form can be bypassed with `....//`. Inspecting `FILES` content (not `FILES_NAMES`) survives extension-renaming bypasses.

## Snort IDS rules (detection, non-blocking)

| SID | Detects | Technique |
|-----|---------|-----------|
| 1000001 | SSH from DMZ host to LAN host | `flow:to_server,established` |
| 1000002 | Any SSH connection attempt to the internal server | `flow:to_server,established` |
| 1000003 | SSH brute force | `flow:to_server,established; detection_filter: track by_src, count 5, seconds 60` |
| 1000004 | SYN port scan | `detection_filter: track by_src, count 5, seconds 10` |

**Design note:** the port-scan rule uses `any` as the source IP because the attacker host sits behind NAT and its real address is translated. `detection_filter` thresholds suppress false positives from single, legitimate connections.

## Conclusion

Effective defense starts with understanding the attack. Each rule here maps directly to a vector that was actually exploited in this environment, specific, tested and documented, rather than a generic ruleset.
